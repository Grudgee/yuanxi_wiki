# 学习范围

本周期读取第14章后段至 §14.8.5“链路均衡概览”，源文本约35,934字符。它承接前周期在 §14.6.2 的断点，重点是 Configuration 的实际训练、L0 的动态改变、Recovery 的触发/返回路径，以及首次进入 8.0 GT/s 后的均衡握手。

## 1. Configuration 训练示例（§14.6.3，PDF p.511–523）

DSP 作为领导者发起链路和 lane 编号工作。示例1中双方只支持单个链路，训练较直接：双方在所有候选 lane 上交换 TS1，确认 Link Number 和 Lane Number 后以 TS2 收束。示例2展示一个有四个面向下游 lane 组的设备，双方可以形成更宽链路；配置必须区分物理 lane、逻辑 lane 和端口方向，不能把到达顺序当作逻辑编号。示例3展示某一 lane 配置失败时的降级/失败路径：不能把缺失 lane 留在“半宽链路”里继续传输，必须按双方支持的合法宽度重新配置或回退。

Configuration.Linkwidth.Start 处理从 Polling 正常结束或恢复状态进入的宽度协商；Linkwidth.Accept 用 TS1 回应并确认可用 lane 集合。Lanenum.Wait/Accept 则对下游/上游方向分别采用相应的编号规则，要求接收端看到稳定、正确的编号。Configuration.Complete 是唯一交换 TS2 的关键次状态，用于确认链路和 lane 编号都已收敛；Configuration.Idle 暂停在最终切换前，等待端口完成进入 L0 的条件。

## 2. L0 正常工作与动态改变（§14.7，PDF p.530–533）

进入 L0 表示物理链路已经训练完成，可以承载 TLP/DLLP。L0 并不意味着速率和宽度永远固定：软件或硬件可请求速率切换、宽度切换，链路伙伴也可能发起改变。任何改变都必须通过 Recovery 等受控状态，先停止按旧参数解释普通数据，再重新锁定和确认。

速率切换会在 Recovery.Speed 协商目标速率；若双方不能稳定工作，必须返回较低速率或失败，不能只看一端发送器已经切换。宽度切换同样需要重新确认 lane 集合和编号；链路伙伴发起变化时，对端必须识别请求并同步进入恢复流程。应用层看到的链路改变应当是一次状态转换，而不是瞬间混合两种速率/宽度的包。

## 3. Recovery 状态（§14.8.1–§14.8.4，PDF p.533–约539）

进入 Recovery 的原因包括失去锁定、错误率/训练条件需要重新建立、速率或宽度改变、低功耗退出，以及均衡失败。Recovery 初始化先发送规定的 TS1/TS2 并重新取得接收器锁定；状态机需区分是保留当前速率恢复，还是进入 Speed 子状态尝试新速率。若目标速率的电气条件不可满足，状态机必须降低速率或回到安全状态。

Recovery 的各次状态要求发送端和接收端在正确次状态交换正确训练序列，并受计时器和连续序列数量约束。速率转换示例显示：先进入恢复、完成速率握手，再在新速率重新获得 bit/symbol lock，之后才回到 L0。恢复中收到普通数据不能被误当作训练成功；训练序列错误、超时或接收条件不稳定都会重新开始/回退。

## 4. Gen3 链路均衡概览（§14.8.5，PDF p.约539–540）

8.0 GT/s 对信号干扰更敏感，固定去加重不足以适应所有通道，因此 PCIe 3.0 引入主动发送均衡。首次达到 8.0 GT/s 后执行均衡，规范强烈建议硬件自动开始；若没有硬件自动机制，必须有软件机制。接收器在每个 lane 上评估输入质量，并向链路伙伴建议满足信号质量所需的发送均衡参数。

均衡过程分四个阶段，当前阶段由接收的 TS1 中 EC（Equalization Control）字段通知。发送器先使用预设/起始系数，再根据接收端反馈调整三抽头 FIR 的参数。均衡成功意味着接收端达到目标信号质量，而不是发送端“发完四阶段”即可。若任一端无法达到目标，LTSSM 将该速率视为不可用，进入 Recovery.Speed 并要求降速。

均衡把第13章的电气机制和本章 LTSSM 连接起来：CTLE/DFE 等 Rx 补偿、Tx pre/main/post cursor、预设和系数比率，必须在训练状态机的受控握手中使用。错误的实现常见于只在理想仿真信道验证，或把均衡参数写死而忽略通道损耗、连接器、封装和 lane 间差异。

## 5. 可复用诊断框架

* 卡在 Configuration：先看 TS1/TS2 中链路/通道编号和双方宽度交集，再看某一 lane 是否无法工作。
* 速率切换后回 Recovery：检查参考时钟、CDR、Tx 去加重/均衡、Rx 眼图和是否满足连续训练序列数量。
* Gen3 只能降速成功：通常说明 8.0 GT/s 信号质量或均衡握手失败，而不一定是事务层软件问题。
* 不能把 L0、Recovery 和 Detect 混为一谈：L0 是业务态，Recovery 是重新同步/改参数，Detect 是电气存在性检测。
