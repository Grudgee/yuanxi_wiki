# 第1章：综合案例、谬误与结论

> 来源：计算机体系结构量化研究方法（第5版）第1章 §1.10–§1.12。
> 本批学习范围：PDF p.80–p.88；书内 p.52–p.60。第1章正文结论到 PDF p.88 / 书内 p.60；PDF p.89 / 书内 p.61 起为 §1.13 习题。

## §1.10 性能、价格与功耗综合案例

本节比较三台 2010 年 Dell PowerEdge 服务器：双路 Intel Xeon X5670 R710（12 核）、双路 AMD Opteron 6174 R815（24 核）和四路 AMD Opteron 6174 R815（48 核）。三者均运行 IBM J9 JVM 与 Windows Server 2008 Enterprise x64，使用 SPECpower 测试服务器端 Java 业务负载（PDF p.80–p.81 / 书内 p.52–p.53）。

- SPECpower 基于 SPECjbb，性能单位为 `ssj_ops`（server-side Java operations per second），会覆盖处理器、缓存、内存系统、多处理器互连、JVM JIT、垃圾回收和部分操作系统行为（PDF p.80 / 书内 p.52）。
- 图 1.18 的基准配置刻意偏向计算：内存少、仅 50 GB SSD，因此不能代表常规服务器配置；这种“benchmarking forces”导致硬件比例失真（PDF p.80–p.81 / 书内 p.52–p.53）。
- 从最大吞吐和 `ssj_ops/$` 看，四路 48 核 R815 最优：约 1.84M `ssj_ops`，约 145 `ssj_ops/$`（PDF p.81 / 书内 p.53）。
- 从功率看，Intel R710 在每个目标负载点的 `ssj_ops/watt` 最高且功耗最低；其总体 SPECpower 效率为 3034 `ssj_ops/watt`，高于双路 R815 的 2357 与四路 R815 的 2696（PDF p.82–p.83 / 书内 p.54–p.55）。
- SPECpower 单值公式：`overall ssj_ops/watt = sum(ssj_ops) / sum(power)`。因为 watt 等于 joule/second，该指标与每焦耳完成的 `ssj_operations` 成比例（PDF p.82 / 书内 p.54）。
- 若再除以价格，R710 为 324 `ssj_ops/watt/$1000`，双路 R815 为 254，四路 R815 为 213。加入功耗后，价格-性能胜者被反转，R710 成为价格-功率-性能综合最优者（PDF p.83 / 书内 p.55）。
- 四路系统功率效率受损的一个原因是 1100 W 大电源对比 R710 的 570 W；电源效率对整机能效很重要，第6章会进一步讨论（PDF p.82 / 书内 p.54）。

## §1.11 谬误与陷阱

### 谬误：多处理器是银弹

约 2005 年转向片上多处理器不是因为并行编程突破，而是 ILP wall 与 power wall 下的现实选择。多核不必然低功耗；其潜力是用多个低时钟、高能效核心替代单个高时钟、低能效核心。性能提升责任更多转移到程序员，程序必须暴露足够并行性（PDF p.83 / 书内 p.55）。

### 谬误：流行版摩尔定律会自动提升性能

“每代技术自动提高性能”的流行说法已不再成立；现在性能提升依赖程序员利用更多并行硬件（PDF p.83 / 书内 p.55）。

### 陷阱：落入 Amdahl 心碎定律

即使熟悉 Amdahl 定律，设计者仍可能未先测量某特性使用率就投入大量优化。局部增强若只覆盖小部分时间，整体加速会被未增强部分限制（PDF p.83 / 书内 p.55）。

### 谬误：单一故障点可接受

可靠性受最弱环节限制。仅冗余电源而不冗余风扇等组件，系统可靠性仍由剩余单点决定；容错系统应避免任一组件故障导致整体停机（PDF p.84 / 书内 p.56）。

### 谬误：提升性能的硬件增强至少不损害能效

Turbo mode 示例显示，2.67 GHz Intel Core i7 提升到 2.94 GHz，性能约提升 1.07 倍，但能量增加 1.37 倍、 watt-hours 增加 1.47 倍。性能提升可能显著恶化能量效率（PDF p.84 / 书内 p.56）。

### 谬误：基准永久有效

基准会被针对性优化和规则解释侵蚀，尤其小内核更容易被“benchmarketing”。SPEC89 的 `matrix300` 中 99% 时间消耗在一行代码，IBM 编译器 blocking 优化带来 9 倍提升，但这不能代表整体程序性能。SPEC 各代淘汰率高，SPEC2000 及更早程序约 70% 在下一代被移除（PDF p.84 / 书内 p.56）。

### 谬误：标称磁盘 MTTF 很大所以几乎不会坏

厂商可能用数千块磁盘短期累计运行时间除以故障数，得到如 1.2M 小时（约 140 年）的 MTTF；这对应持续更换磁盘的假设，而非单盘寿命。更实用的是年故障率。1000 块 1M-hour MTTF 磁盘全天运行时，年故障约 `1000×8760/1e6 ≈ 8.76` 块，即 0.9%/年，5 年约 4.4%。真实环境研究为 2%–10%/年，实际 MTTF 比厂商标称差约 2–10 倍（PDF p.84–p.85 / 书内 p.56–p.57）。

### 谬误：峰值性能能预测实际性能

四个程序在四种多处理器系统上的峰值性能利用率仅 5%–58%。峰值只保证不会超过，不能可靠预测实际表现（PDF p.85–p.86 / 书内 p.57–p.58）。

### 陷阱：故障检测本身不会降低可用性

某些状态不影响正确执行，如分支预测器错误只影响性能，死寄存器错误不影响结果。若检测到这类非关键故障就崩溃程序，会不必要地降低可用性。Sun E3000–E10000 的外置 L2 cache 只有 parity 没有 ECC，脏数据 parity 错误只能报告并崩溃；超过 90% 现场检查未发现其他问题。后续 Solaris 通过 cache scrubbing 降低影响。教训是不要只提供检测而不提供恢复机制（PDF p.85–p.86 / 书内 p.57–p.58）。

## §1.12 结论与后续入口

- 第1章建立了贯穿全书的量化框架；从第5版起，能量效率成为与性能并列的核心目标（PDF p.87 / 书内 p.59）。

- 第3章讨论指令级并行，包含静态与动态方法、ILP 极限及多线程入门；附录 C 提供流水线入门（PDF p.87 / 书内 p.59）。
- 第4章讨论数据级并行的三条路线：向量架构、SIMD 指令扩展和 GPU 内部视角（PDF p.87 / 书内 p.59）。
- 第5章讨论多处理器与多指令流并行（PDF p.87–p.88 / 书内 p.59–p.60）。
- 附录 A–L 涵盖指令集原理、缓存、流水线、向量、VLIW/EPIC、大规模科学计算、算术、ISA 调查与历史资料；本 PDF 后续应按目录精确核验各附录入口（PDF p.88 / 书内 p.60）。
